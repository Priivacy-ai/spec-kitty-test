## Architecture Decisions

### Decision 1: Auto-Skip jj Tests

**Choice**: Use `@pytest.mark.jj` with auto-skip when jj unavailable

**Rationale**:
- CI/CD environments may not have jj installed
- Allows git-focused tests to run regardless
- Matches spec-kitty's existing pattern

**Implementation**:
```python
# conftest.py
import shutil
import pytest

def pytest_configure(config):
    config.addinivalue_line("markers", "jj: tests requiring jujutsu")

@pytest.fixture(scope="session")
def jj_available():
    """Check if jj is installed and functional."""
    if shutil.which("jj") is None:
        return False
    try:
        result = subprocess.run(["jj", "--version"], capture_output=True)
        return result.returncode == 0
    except Exception:
        return False

def pytest_collection_modifyitems(config, items):
    """Auto-skip @pytest.mark.jj tests when jj unavailable."""
    if shutil.which("jj") is None:
        skip_jj = pytest.mark.skip(reason="jj not installed")
        for item in items:
            if "jj" in item.keywords:
                item.add_marker(skip_jj)
```

### Decision 2: Parametrized Backend Testing

**Choice**: Use pytest parametrization for git/jj parity tests

**Rationale**:
- Ensures both backends tested with same scenarios
- Reduces code duplication
- Clear test output showing which backend tested

**Implementation**:
```python
@pytest.mark.parametrize("backend", [
    "git",
    pytest.param("jj", marks=pytest.mark.jj)
])
def test_workspace_creation(backend, spec_kitty_project):
    """Test workspace creation for both backends."""
    ...
```

### Decision 3: Distribution Test Isolation

**Choice**: Distribution tests explicitly unset `SPEC_KITTY_TEMPLATE_ROOT`

**Rationale**:
- Validates real PyPI user experience
- Catches template bundling bugs (like the 0.10.8 catastrophe)
- Per constitution: "Test what you ship"

**Implementation**:
```python
@pytest.fixture
def no_template_bypass(clean_env):
    """Ensure no template root bypass for distribution tests."""
    os.environ.pop("SPEC_KITTY_TEMPLATE_ROOT", None)
    os.environ.pop("SPEC_KITTY_REPO", None)
    yield
```

### Decision 4: Test Project Fixtures

**Choice**: Create isolated spec-kitty projects per test

**Rationale**:
- Full isolation between tests
- Clean VCS state for each test
- Realistic user environment simulation

**Implementation**:
```python
@pytest.fixture
def spec_kitty_project(tmp_path):
    """Create an initialized spec-kitty project."""
    project_dir = tmp_path / "test-project"
    project_dir.mkdir()
    subprocess.run(["git", "init"], cwd=project_dir, check=True)
    subprocess.run(["spec-kitty", "init"], cwd=project_dir, check=True)
    return project_dir
```
