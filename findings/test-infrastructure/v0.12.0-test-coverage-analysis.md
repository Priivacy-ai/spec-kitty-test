### Critical Infrastructure Fix: Sparse-Checkout

**Problem Solved**: Original workspace-per-WP design had each worktree copy `kitty-specs/` files locally. Status updates were worktree-local → massive state divergence.

**Solution**:
1. Git sparse-checkout excludes `kitty-specs/` from worktrees
2. Auto-commit all status changes to main branch
3. Agents read/write to main repo via absolute paths
4. Multiple agents stay synchronized

**Implementation**:
- `implement.py` lines 596-642: Configure sparse-checkout on worktree creation
- `tasks.py`: Auto-commit in `move-task` and `mark-status` commands
- `workflow.py`: Auto-commit when `implement`/`review` commands claim WPs
- Helper: `fix-worktrees-to-sparse-checkout.sh`

**Existing Tests**: **ZERO**

**Critical Behaviors Untested**:
1. ✗ Sparse-checkout correctly excludes kitty-specs/
2. ✗ Agents read from main repo via absolute paths
3. ✗ Status changes auto-commit to main
4. ✗ Multiple parallel worktrees stay synchronized
5. ✗ Clean merges (no conflicts from sparse-checkout)
6. ✗ Feature slug detection strips -WPxx suffix
7. ✗ PID tracking captured and stored

**Risk**: This is the foundation of workspace-per-WP. Without tests, we have NO confidence it works correctly.

From `CLAUDE.md`:

> "Test what you ship, not just what you write."

1. **Functional tests**: Fast iteration, uses SPEC_KITTY_TEMPLATE_ROOT

**The Catastrophic Bug** (Issues #62-64):
- **Affected**: 100% of PyPI users
- **Duration**: 8+ releases
- **Passed tests**: 323
- **Root cause**: ALL tests used local templates, bypassed pip package

**Lesson**: Distribution tests are mandatory for release validation.
